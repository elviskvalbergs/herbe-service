# WS12 — Documents: order report PDF + DOCX template engine

Date: 2026-07-20. Branch: `feature/service-phase1-ws12-documents` (worktree off `origin/preview` @ 67276e0). Author session: "service ws12".

Scope source: `docs/21-phase-1-implementation-plan.md` §WS12, `docs/12-documents-templates.md` (all), `docs/adr/0004-pdf-rendering-approach.md`, `docs/24-phase1-status-and-parallel-handoff.md` §1/§4 (WS12 "Not started", ready-to-assign job 1: "worksheet/order report PDF+DOCX engine … new `lib/documents/**` + a route; no overlap with sync code").

## What this slice ships

1. **Seeded default order-level report PDF** — renders all approved worksheets of an order as one themed HTML document → PDF, crew merged by `crewGroupId`, zero authoring (doc 12 §Phase 1).
2. **DOCX template engine** — placeholders (dot-paths), loops, conditionals, localized date/number formatting, images (tenant logo), plus upload-time validation (unknown placeholders / loop errors).
3. **Document number series** — per (tenant, docType), assigned at first final render, immutable after; re-renders create new versions sharing the number.
4. **Queued render pipeline** — render job enqueued atomically with worksheet approval, processed off the critical path by a cron tick; retries with backoff → dead.
5. **PDF converter implementation per ADR 0004** — Gotenberg HTTP client (HTML→PDF + DOCX→PDF through one service).
6. **Minimal admin API** for templates (upload with validation, list, test-render) — the library *UI* is WS14 A9, not here.
7. `reportPdf` flag in the frozen `/api/ext` DTO flips from hardcoded `false` to real availability (value change only — shapes untouched).

## Decisions — all FINAL

1. **Converter = Gotenberg** (confirms ADR 0004's recommendation; addendum added to the ADR in this slice). Client in `lib/documents/convert/gotenberg.ts` using global `fetch` with `GOTENBERG_URL` env. When unset/unreachable, render jobs stay queued and retry — graceful degradation, no approval blockage (rendering is already off the critical path). Production deployment of a Gotenberg container is an infra decision recorded as open in the ADR addendum — the engine is fully testable without it (mocked unit tests + a `RUN_GOTENBERG_TESTS=1`-gated live smoke against a local docker Gotenberg).
2. **DOCX engine = docxtemplater ^3 (MIT core) + pizzip**, wrapped behind our own `lib/documents/docx/engine.ts` API so the dependency never leaks. Custom parser resolves dot-paths (`{customer.name}`) and formatter pipes (`{order.requestedAt | date}`, `| number`, `| currency`) via `Intl` with the tenant locale. Loops = docxtemplater sections `{#rows}…{/rows}`; conditionals = the same section mechanism on booleans (`{#warranty}…{/warranty}`) — docxtemplater's native semantics, documented in the field catalog. Images (v1: tenant logo via `{%logo}`) through a minimal custom docxtemplater module we write ourselves (~50 lines) — the official image module is paid and the community fork is unmaintained; ours supports fixed-size PNG/JPEG only.
3. **Storage = Postgres bytea** on the `documents` table (`docx_bytes`, `pdf_bytes`). Doc 12 wants Media records in Supabase Storage, but zero media/storage infra exists anywhere in the repo (verified 2026-07-20) and standing up object storage is not this slice. Fine at pilot scale; migrating to the real media store when WS1/WS9 build it is a recorded deferred item. All reads/writes go through `lib/documents/store.ts` so the swap is one module.
4. **Data model (migration 0021, idempotent):**
   - `document_templates` — `id uuid pk, tenant_id, doc_type text, name text, version int default 1, docx bytea, active boolean default true, created_at`. Selection v1: newest active template for (tenant, docType), else built-in. The doc-12 rule chain (work type / model category / customer class…) is deferred.
   - `document_number_series` — `id, tenant_id, doc_type, prefix text, next_counter int default 1, created_at`, unique `(tenant_id, doc_type)`. Auto-seeded on first use with a per-type default prefix (`SR` for `order_report`, `OC` for `order_confirmation`). Number format: `<prefix>-<year>-<counter padded 5>` (doc 12's `FSC-2026-00142` example). Counter monotonic, no yearly reset (deferred).
   - `documents` — `id, tenant_id, doc_type, order_id, number text, series_id, version int, template_id nullable (null = built-in), template_version nullable, context_snapshot jsonb, docx_bytes nullable, pdf_bytes nullable, rendered_at, created_at`. Unique `(tenant_id, doc_type, order_id, version)`. A row is only inserted on successful render (status column unnecessary); version = prior max + 1; number copied from version 1 (immutability enforced + tested).
   - `document_render_jobs` — `id, tenant_id, erp_company_id nullable, doc_type, order_id, trigger text ('approval'|'manual'), status text ('queued'|'running'|'done'|'dead'), attempts int, next_attempt_at, last_error, created_at, updated_at`. Coalescing enqueue: an existing `queued` job for (tenant, order, docType) absorbs the new trigger (no duplicate). Backoff `2^attempts` minutes, dead after 8 attempts — the WS4 push-queue idioms.
5. **Merge context** (`lib/documents/context.ts`): root = ServiceOrder. Includes order fields, customer, siteName, service items of the order rows, and **all worksheets in status `Approved` OR `Synced`** (a pushed worksheet is `Synced` — approval-then-push must not drop it from the report), each with rows, time entries (total minutes), distance entries, technician display name, `signedOnSite`. Crew merge: worksheets sharing a non-null `crewGroupId` render as one section with technicians listed together (doc 12 §Merge context). Read-only projection; `computed: {}` placeholder key reserved for WS6's sandbox. Snapshot stored on the document row (doc 12 §Versioning).
6. **Built-in report** (`lib/documents/builtin-report.ts`): pure function context+branding → HTML string (no React), themed via `tenants.branding` — **new nullable jsonb column** `branding` on `tenants` (shape: `{ locale?, logoUrl?, accentColor?, footerText? }`, defaults: `en` + neutral herbe styling). Additive only; WS1's real theming/settings model supersedes it later (recorded in doc 24 §2). Photos/signature images are NOT in v1 — no media infra exists to source them from (deferred, doc 12 lists them for the built-in report).
7. **Approval hook**: `enqueueDocumentRender(tx, …)` called inside `approveWorksheet`'s existing `db.transaction` (lib/sync/push/enqueue.ts) right after `setWorksheetStatus(tx, …, 'Approved')` — render job commits atomically with approval, mirroring the push-group enqueue. Enqueue failure = approval failure (same-tx semantics are the point).
8. **Cron**: `GET /api/cron/documents-tick` — CRON_SECRET bearer + `acquireCronLock('documents-tick', 55)` + per-job try/catch isolation, `* * * * *` in `vercel.json`. Mirrors push-tick exactly.
9. **Admin routes** (ADMIN_MIGRATIONS_SECRET bearer, fail-closed, static error strings — the push-retry idiom): `POST /api/admin/document-templates` (JSON body: tenantId, docType, name, docxBase64; runs engine validation, 422 with report on hard errors), `GET /api/admin/document-templates?tenantId=` (metadata only, no bytes), `POST /api/admin/document-templates/test-render` (templateId + orderId → runs the full merge+convert, returns validation report + sizes, never file bytes).
10. **`reportPdf` flip**: `lib/api/ext` worksheet routes resolve "a rendered order_report PDF exists for this worksheet's order" and pass it to the mapper (mapper stays pure; frozen shapes untouched — only the hardcoded `false` becomes real).
11. **Coverage**: add `lib/documents/**` to the per-path **90%** gates in vitest.config.ts (adding a gate, never lowering).
12. **Not in this slice** (deferred, recorded in doc 24 §4): computed-fields JS sandbox (WS6 owns the shared sandbox; `computed` key reserved), template library UI + field-catalog browser (WS14 A9), selection rule chain, per-worksheet internal render variant, photos/signature/QR images in documents, delivery email, `/api/ext/v1/orders/{id}/report` endpoint (Phase 2 per doc 12 §roadmap), manual "Generate document…" UI entry points (F4/O2 — WS9/WS10), Supabase Storage migration, yearly counter reset, order-confirmation *seeded* template (the `order_confirmation` docType is accepted by the engine for custom templates; no built-in).

## Tasks (one subagent each, TDD, commit per green task)

1. **Migration 0021 + drizzle schema** — four tables + `tenants.branding`; migration-shape tests (idempotent re-run).
2. **Number series store** (`lib/documents/number-series.ts`) — `assignNumber(tx, {tenantId, docType, year})`: auto-seed row, atomic `UPDATE … RETURNING` increment (race-safe test: two concurrent assigns → distinct numbers), formatting.
3. **Merge-context builder** (`lib/documents/context.ts`) — golden-fixture tests: solo order, crew order (merge by crewGroupId), mixed statuses (Draft/Rejected excluded; Approved+Synced included), rows/time/distance totals.
4. **DOCX engine** (`lib/documents/docx/engine.ts` + logo module) — deps: docxtemplater+pizzip. Tests build minimal DOCX fixtures programmatically (pizzip) and assert merged XML: placeholders, dot-paths, `| date`/`| number`/`| currency` localization (lv vs en), loops, conditionals, logo module, validation report (unknown placeholder, unclosed loop).
5. **Gotenberg client + built-in report** (`lib/documents/convert/gotenberg.ts`, `lib/documents/builtin-report.ts`) — client: multipart POST to `/forms/chromium/convert/html` and `/forms/libreoffice/convert`, timeouts, typed errors incl. unconfigured; unit tests against a local in-test HTTP stub; `tests/gotenberg/` live smoke gated on `RUN_GOTENBERG_TESTS=1`. Report: HTML snapshot-ish assertions (sections per crew group, totals, branding, escaping).
6. **Document + render-job stores and engine** (`lib/documents/store.ts`, `lib/documents/render/{store,engine}.ts`) — coalescing enqueue, `processRenderJobs(db, {now})`: claim queued due jobs, build context, template-else-builtin render, convert, insert document (version/number rules), done; failure → backoff/dead. Number immutability + version increment tests; converter-down test (job stays queued, attempts++).
7. **Wiring** — approval hook in `approveWorksheet` (existing enqueue tests extended: approval inserts a render job atomically; approval still fails if enqueue fails), cron route + vercel.json, `reportPdf` flip in ext route+mapper (route test: false before render, true after).
8. **Admin template routes** — the three routes per decision 9, route tests (401 fail-closed, 422 validation, happy paths).
9. **Docs + gates** — ADR 0004 addendum, doc 24 update (§1 status, §2 infra bullet for `tenants.branding` + document tables, §4 deferred list, "Last updated"), CRON handoff equivalent if this repo has one (it does not — vercel.json is authoritative here), final full verification, push.
